# CIM Event Stream Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create the `agentshield_cim_event` stream and two normalizing MVs in `init.go`, then migrate all 4 rule seed YAMLs to query the CIM stream instead of `agentshield_hook_events`.

**Architecture:** Two Materialized Views (`mv_cim_claudecode`, `mv_cim_openclaw`) read `agentshield_hook_events` and write normalized rows to `agentshield_cim_event`. The backend creates all three on startup via `execIfNotExists`. Rule seed YAMLs are updated so newly installed or upgraded rules query the CIM stream.

**Tech Stack:** Go 1.21, Timeplus Proton (streaming SQL), YAML seed files

## Operational Note

The seed file changes affect **future rule installations only**. Rules currently installed (`mv_rule_rp001`–`mv_rule_rp004`) were created from the old SQL and must be explicitly uninstalled and reinstalled (Task 7, Step 5) to pick up the CIM-based SQL. This is by design — the existing rule MV lifecycle is not changed.
